# 交互样机收口与后续开发计划

日期：2026-10-28。依据：用户对 0.3.0 的反馈和“这一阶段如何结束、下一步做什么”的问题。

状态更新：用户体验 0.5.0 后表示“基本上这一版没啥问题了”。据此将 0.5.0 记录为本阶段通过的视觉与交互基线，交互样机阶段收口，下一阶段进入真实数据闭环。此认可不扩展为尚未实施的持久化、备份或完整兼容性验收。

2026-10-29 更新：第一轮真实数据闭环 0.6.0 已完成自动验证并安装到手机，具体范围与后续缺项见 [交付记录](本机数据闭环-0.6.0.md)。下一轮进入完整编辑、移动归属与周计划；备份和完整兼容性验证仍待实施。

## 本阶段如何结束

本阶段验证视觉与交互方案，不以无限调参作为开发流程。以以下六项作为本轮集中验收范围；已经通过的项目形成基线，后续仅因明显回归或功能落地需要调整。细微偏好优化记录到后续迭代，不阻塞所有业务开发。

| 验收项 | 通过标准 | 当前状态 |
| --- | --- | --- |
| 关系图居中 | 初始概览内容居中；拖动、缩放、概览仍可用 | 0.5.0 基线，用户本阶段体验认可 |
| 玻璃 | 可辨背后节点的模糊轮廓，前景文字清楚；第一帧使用最终材质 | 0.5.0 基线，用户本阶段体验认可 |
| 日期表单 | 选项、表头、日期数据有层级；可选日期、清除并正确保存 | 0.5.0 基线，用户本阶段体验认可 |
| 材料与说明 | 分支有独立创建入口；说明先标题后正文、外部仅标题，点击查看正文；材料可选择并复制 | 0.5.0 基线，用户本阶段体验认可 |
| 任务板与行动 | 整张收起卡片可点；两页同款展开、连续操作可中断、标题不裁切 | 0.5.0 基线，用户本阶段体验认可 |
| 悬挂卡片 | 展开聚焦，尺寸连续变化，改善收起加载和重复定位；圆角略增 | 0.5.0 基线，用户本阶段体验认可 |

助手负责构建、规则与界面检查、对照截图及修复可复现问题；用户在手机上集中验收这六项的手感与材质。通过后保存界面基线，进入真实业务开发。模拟器通过不代替用户手机上的体验，也不意味着所有 Android 版本和性能项目已验收。

## 下一阶段：完成真实数据闭环

1. 建立 Room 数据表、稳定 ID、关联约束和初始迁移；设置接入 DataStore。把样机内存仓储替换为持久仓储。
2. 先交付一条可用流程：创建对象/任务 → 安排引用日程 → 任意页面完成同步 → 退出并重开仍保留。通过这条链路确认架构再展开其他功能。
3. 扩展材料与说明的正式保存、编辑、打开及错误恢复；材料元数据、文件副本和对象关系一同管理，处理复制失败与无引用文件清理。0.4.0 已可复制文件，但元数据仍属本次演示会话。
4. 接入周计划按周保存、历史查看；补齐任务和对象编辑、移动归属、日程单独显示名称等已确认规则。

每个小步骤都给出可安装版本及明确验收流程，不等到所有功能完成才第一次使用真实数据。

## 随后：删除、备份与可靠性

按已确认规则实现对象级联删除、任务关联日程删除和短暂撤销；完成包含材料/背景/设置/布局的完整备份。恢复时先校验并保存当前快照，再整体替换，失败保留原数据。通过故障与恢复验证后再用于保存用户重要内容。

## 最后：兼容与发布准备

覆盖 Android 12 至主验收设备版本、系统字号与减少动画、权限取消、文件错误、旋转/生命周期及连续手势性能。修复影响使用的问题，整理正式图标、版本与发行构建。云同步、账号、系统通知和 deadline 页面仍不在第一版新增范围中。
