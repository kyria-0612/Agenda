# 关键状态与验收说明

日期：2026-10-20  
阶段：浏览器交互原型 → 关键状态补齐（首批）

2026-10-29 更新：本页早期浏览器记录保留为历史依据；Android 当前实现及实际覆盖见《文档对照与发布检查-0.11.0》。尽快做的今天至第六天、排除逾期边界已获用户明确确认，覆盖下方早期待确认标记。

本轮沿用现有页面和玻璃浮层，不改变导航结构。以下为已实现的原型规则；手机上的系统文件查看器、前后台行为和手势仍需 Android 样机验证。

## 状态与处理

| 场景 | 原型行为 | 验收方法 |
|---|---|---|
| 事项为空 | 关系视图、任务板都显示说明与“新建任务”入口 | 使用空数据，分别切换两种视图并创建任务 |
| 行动类别无任务 | 显示“还没有这类任务”，展开后可新建 | 创建时选择对应类别，返回后应立即出现 |
| 行动类别全部完成 | 显示“这一类任务都完成了”，保留查看事项入口 | 在事项中取消完成，任务应重新进入行动卡片 |
| 本周无计划 | 显示轻量说明，保留添加入口 | 新增计划后空说明消失 |
| 搜索未输入 / 无结果 | 分别显示输入提示和没有相关内容 | 输入空白、不存在的关键词；覆盖对象、任务、材料、说明 |
| 当天时间段无安排 | 继续使用“留白”，提供添加入口 | 完整卡片可按时段添加；悬挂展开卡片可添加当天日程 |
| 无可引用的未完成任务 | 提示切换临时日程项，禁用引用提交，隐藏空选择框 | 全部任务完成后打开添加日程，切到临时项后可输入并添加 |
| 日程类型切换 | 保留本次输入的临时内容和所选引用任务 | 临时项输入文字 → 引用任务 → 临时项，文字应恢复 |
| 重复引用日程 | 相同任务、日期、时段、具体时间重复时阻止提交并提示 | 再次提交完全相同安排；改变时段或时间应允许 |
| 必填内容为空 | 说明标题、周计划、休闲活动、临时日程项和材料选择使用持续的行内错误并聚焦字段；快捷创建保留原有行内错误 | 空提交后填入内容，错误应清除 |
| 未保存关闭 | 输入或修改后关闭、按 Escape 或使用主导航，会出现“继续编辑 / 放弃编辑” | 继续编辑保留当前表单；放弃编辑才关闭或切换页面 |
| 图片读取中 / 失败 | 保存期间按钮禁用、显示“正在保存…”；失败保留表单并显示错误 | 使用无效图片验证失败；失败前的文字和背景不写入数据 |
| 示例材料未关联 | 明确说明是示例，提供同名文件关联入口 | 选择不同文件名报错，同名文件关联后显示打开链接 |
| 上传材料刷新后失效 | 明确提示文件连接失效，可重新选择同名文件 | 刷新后重新关联，沿用同一材料条目，不新增副本 |
| 本机保存失败 | 页面持续显示“尚未存到本机”，可重试；成功提示同时附带未保存说明 | 模拟存储写入失败，恢复后重试；刷新前有浏览器离开提示 |
| 本机数据损坏 | 使用安全空内容，提示原始内容保留并提供导出；首次写入前备份损坏原文 | 使用无效 JSON 或无效条目；检查原键未被静默覆盖，成功保存前写入 recovery 备份 |
| 任务完成 / 恢复 | 日程引用共用任务完成状态；同一任务多个引用同步；临时日程仅影响自己 | 从日程勾选、取消，再查看事项与行动 |
| 今天到期 / 已逾期 | 任务列表标注“今天到期”“已逾期”，完成后不再显示这两个待办提示 | 覆盖昨天、今天、明天、已完成、有无期限 |

## 每日提醒规则

- 设备本地日历日：排除今天，从明天起连续三个自然日，包含第三天。
- 过滤已完成与无截止日期任务；今天到期和逾期任务仍在事项中查看，不混入这份提醒。
- 同一日期自动检查一次；没有符合条件的任务时安静跳过，当天后续新增任务不再次自动弹窗。
- 点击提醒内任务可打开任务详情。关闭后当天不自动重复。
- 页面打开、返回前台、窗口重新获得焦点时检查；页面持续打开时每分钟检查日期是否变化。日期变化更新日程日期范围。
- 已有编辑浮层时推迟检查，避免覆盖当前编辑；下一次检查再尝试。自动提醒不使用延迟弹窗。
- 存储不可用时本次页面仍按日期去重；重新加载后的跨会话去重无法保证。

## 数据与恢复边界

- 第一次运行仍加载演示数据；空状态用于已有数据为空的情况，自动检查使用独立测试数据，不清空日常使用数据。
- 存储失败后修改留在当前页面内存中；用户刷新或关闭会丢失尚未保存的数据。持续提示与离开提醒用于说明这一状态。
- 损坏原文保存在原存储键；首次成功保存前复制到 `agenda-interaction-prototype-v1-recovery`，可在恢复保存前点击导出原文。未增加完整备份导入产品流程。
- 文件仍仅在本次会话保留打开链接；同名重新关联不会校验文件内容是否相同。浏览器能否预览 PDF/PPT 等取决于其支持能力。
- 本次关闭保护按“发生过输入或选项修改”判断，不比较修改前后是否完全一致。任务/对象创建类型切换沿用原有“仅保留名称”规则。
- 没有新增删除、云同步或网络请求流程；不引入这些流程对应的加载状态。

## 新增需求验收：行动页「尽快做」（2026-10-20）

状态：Android 内存动效样机已提供本节功能的首批实现、规则测试和模拟器验证，浏览器原型尚未修改。上文 15 项通过记录不包含本节；本节整表及 Android 真机验收仍未全部完成。

已确认功能范围见 [技术架构决策记录](技术架构决策记录.md) D21、D22；筛选、日期边界、空态和并列排序的实现建议见 [产品需求与设计决策](产品需求与设计决策.md) 第 3.4 节。下表中涉及这些建议的预期，须在边界核对后作为最终验收标准。

| 场景 | 预期 / 建议行为 | 验收方法 |
| --- | --- | --- |
| 位置与范围 | 行动页原四张卡片下新增「尽快做」；不新增 deadline 页面或导航入口 | 检查页面顺序、滚动和底部导航遮挡 |
| 多于三个候选 | 按截止日期从近到远仅显示前三个；任务只出现一次 | 准备至少五个不同截止日期任务，以及同任务的多条日程引用 |
| 少于三个候选 | 仅显示实际任务，不用范围外任务补足 | 分别准备一项、两项；另加一周外任务 |
| 无候选 | 建议保留卡片并显示「一周内暂无待完成任务」 | 准备空库或全部候选完成的情况 |
| 日期边界 | 2026-10-29 已确认今天至今天后第六天均包含，后第七天排除，逾期不纳入 | 若今天是 10 月 20 日，覆盖 19、20、26、27 日，另测跨月、跨年 |
| 排除项与类别 | 建议排除已完成、无期限、已删除任务；未分类和对象所属任务正常参与 | 混合这些状态，确认不按类别、意愿或日程安排限制候选 |
| 并列截止日期 | 建议用稳定 ID 作为最终排序，不因刷新或切页随机跳动 | 准备同日到期任务，反复进入与刷新 |
| 完成与恢复 | 建议与共享任务同步，完成后移除并补入下一候选，恢复未完成后重新排序 | 从尽快做、事项、引用日程分别改变完成状态 |
| 改期、删除与撤销 | 建议自动移出或重新排入候选，无悬空条目 | 更改前三项期限、删除、短暂撤销，再核对顺序 |
| 跨日、返回前台与时区变化 | 建议按设备当前本地日期重新计算，日程钟点不换算 | 持续前台跨日、后台跨日后返回，以及切换时区 |
| 与每日提醒独立 | 尽快做按一周规则持续展示；每日提醒仍排除今天、明天起三天且每日去重 | 当天关闭每日提醒后检查尽快做仍可查看，不新增系统通知 |

具体卡片宽度、展开方式与动效在保持原四卡结构和既定视觉风格的前提下校准，本次文档更新不宣称相关视觉参数已定稿。
